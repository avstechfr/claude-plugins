# V2 vs V3 — repères pour le dépannage

> **Ne jamais deviner la version.** Faire lire la version dans l'écran d'accueil de Logic'S ou
> dans les propriétés de l'exe (`(Get-Item "C:\LogicS\Logic'S - Encaissements.exe").VersionInfo.FileVersion`).
> Le diagnostic diverge complètement selon la version, et un parc peut être en version mixte.

## Ce qui ne change pas entre V2 et V3

- **Socle technique** : WinDev (PC SOFT) / WLanguage, base **HFSQL** Classic ou Client/Serveur,
  Windows.
- **Arborescence** : `C:\LogicS\` avec `data\` (dont `Params.ini`), `Sauvegardes\`, `Documents\`,
  `Raz\`, `Images\`, `logs\`, `PrintS\` (serveur d'impression), `MAJ_loc\`.
- **Ports et protocole de l'Automate** : identiques. Un client (Gestion, Encaissements, Mobile,
  Flow) qui parle à l'Automate n'a pas besoin de savoir si le poste est en V2 ou V3.
- **Certification NF-525** côté caisse : la chaîne fiscale se calcule localement, pas dans le Cloud.

## La différence structurante : qui écrit la chaîne fiscale

| | V2 | V3 |
|---|---|---|
| Écriture des tickets, JET, signature, numérotation | **Encaissements** lui-même | **Automate V3 uniquement** |
| Rôle d'Encaissements | Tout | UI caissier, claviers, staging (`Caisse_Table_Encours`, `Caisse_Commande_Encours`), affichage ticket |
| Conséquence en dépannage | Un ticket manquant se cherche côté caisse | Un ticket manquant se cherche **côté Automate V3** (jobs, worker, logs) |

En V3, **aucune autre application** (Encaissements, Pad mobile, Totem, ComCom) n'écrit dans les
tables fiscales : elles postent un job dans `Api_Jobs` avec la cible `AUTOMATE`. Un seul service
Automate par établissement = un seul écrivain fiscal, donc pas de concurrence par construction.

**Ce que ça veut dire en intervention V3** : « le ticket n'est pas passé » se diagnostique en
regardant si le job a été créé, s'il a été récupéré par le worker, et pourquoi il a échoué —
pas en cherchant un bug d'écriture dans la caisse.

## L'Automate

Service local qui tourne sur chaque poste Logic'S, pilote les autres exécutables (Encaissements,
Serveur d'Impression, Precia Connector), surveille la caisse par heartbeat, et télécharge les
mises à jour depuis le serveur de caisse.

| | V2 | V3 |
|---|---|---|
| Exécutable | `Logic'S - Automate.exe` | `Logic'S - Automate V3.exe` |
| Mode | exe utilisateur | à partir de la 3.1.0 : **vrai service Windows** (démarre avant la session, survit à la déconnexion) |
| API supplémentaire | — | **API locale HTTPS port 8443** (REST, JWT + scopes) |

### Ports

| Socket | Port | Bind | Rôle |
|---|---|---|---|
| `AUTOMATE` | `24000 + n° de poste` | `127.0.0.1` (depuis 2.9.9.50 / 3.0.1.1) | Commandes venant de Gestion / Encaissements |
| `SERVEURMOBILE` | `25100 + n° de poste` | `0.0.0.0` | Connexion des tablettes Logic'S Mobile depuis le LAN |
| API locale V3 | `8443` | HTTPS | REST isomorphe Cloud (V3.1+) |
| Serveur de caisse (HTTP MAJ) | `2212` | — | Téléchargement des mises à jour |

Exemples poste 1 : AUTOMATE = `24001`, SERVEURMOBILE = `25101`.

> **Jamais deux Automates actifs sur le même poste** (V2 et V3 en même temps) : conflit de port
> sur `24000 + n° de poste`.

> La socket mobile renvoie les **credentials HFSQL en clair** dans sa réponse `INIT`. Elle ne
> doit jamais être exposée hors du LAN client.

### Dépannage Automate — table des symptômes

| Symptôme | Cause probable |
|---|---|
| Connexion TCP refusée sur 24000+N | L'Automate n'est pas lancé ; ou le client se connecte via une IP LAN alors que la socket bind `127.0.0.1` depuis 2.9.9.50 / 3.0.1.1 ; ou le n° de poste utilisé pour calculer le port ne correspond pas |
| Connexion OK mais aucun retour | Le client n'a pas laissé ≥ 50 ms entre deux envois : les commandes sont lues en bloc et ne matchent pas |
| `DEMARRE_FR` répond mais la caisse ne se lance pas | La caisse est déjà considérée active : `DEMARRE_FR` ne fait rien. Utiliser `REDEMARRE_FR` |
| Le watchdog ne relance pas une caisse plantée | Vérifier que le client envoie bien un `HEARTBEAT_FRONT` périodique (< 30 s) |
| Socket mobile qui répond en caractères bizarres | Messages mobiles en UTF-16LE côté WinDev Mobile ; conversion faite en lecture mais pas en écriture — décoder correctement côté client |
| `MAJ_EXEC` télécharge mais rien ne se lance | Comportement normal : le lancement de `MAJ.exe KILLUA` est commenté dans le code |
| Port 2212 injoignable depuis un poste | Le serveur de caisse est down ou n'expose pas le HTTP sur 2212 |
| Le socket n'a pas pu s'ouvrir | Depuis 2.9.9.50, l'Automate le trace explicitement : lire `C:\LogicS\logs\` |

Beaucoup de bugs historiques de l'Automate (watchdog qui tue la caisse à minuit, watchdog qui
tue l'Automate lui-même, 2ᵉ connexion sans réponse, RCE via `EXECUTE` sur socket exposée LAN)
sont **corrigés en 2.9.9.50 (V2) / 3.0.1.1 (V3)**. Face à un de ces symptômes : commencer par
vérifier la version installée, la mise à jour est souvent le correctif.

## Logic'S Mobile (pads / pockets)

- V2 : Logic'S Mobile (WinDev Mobile), se connecte à la socket `SERVEURMOBILE`.
- V3 : refonte Flutter (Pad mobile), passe par l'API locale de l'Automate V3.
- Les pads et les caisses **partagent la même base** : un système mixte (caisse en version X,
  pad resté en version Y) produit des incohérences difficiles à diagnostiquer. Toujours vérifier
  **les deux versions**, caisse *et* pad.
- Les logs du pad sont sur le pad. Sur les versions récentes de Logic'S Mobile, la trace des
  manipulations utilisateur est écrite inconditionnellement dans `LogicS_Mobile_AAAAMMJJ.log` —
  sur les versions plus anciennes il n'y a **rien d'exploitable en production**, il faut brancher
  le pad et récupérer ce qui existe.

## Autres composants de la gamme

| Composant | Ce que c'est |
|---|---|
| Logic'S Gestion | Back-office : articles, clients, tarifs, exports comptables, envoi articles balances |
| Logic'S Synchro | Synchronisation multi-sites HFSQL |
| Logic'S Cloud | Backend Node.js + PostgreSQL — **miroir** de la caisse (voir `poste-reseau-cloud.md`) |
| Logic'S Totem | Borne de commande (Flutter) |
| Logic'S ComCom | Commandes / click & collect (Flutter) |
| Logic'S Flow | Sauvegardes côté client |
| Serveur d'Impression | `PrintS\Logic'S - Serveur Impression.exe`, piloté par l'Automate |

## Vérifications de version à faire en début d'intervention

1. Version de l'exe **Encaissements** sur le poste concerné.
2. Version de l'**Automate** (V2 ou V3, et numéro).
3. Version sur les **autres postes** — un parc en version mixte est une cause de bug à part entière.
4. Version des **pads**, si le client en a.
5. `VERSION_BO` dans `Params.ini` (version du back-office attendue).

Si les versions divergent dans le parc, le signaler au technicien : c'est souvent la vraie cause,
et une remise à niveau vaut mieux qu'un contournement.
